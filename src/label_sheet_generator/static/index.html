How it works

  1. 1

    Pick a sheet

    A label template is a JSON file under data/templates/labels/. It declares the page size, the grid (rows, columns, margins, gaps, label size) and the elements printed inside each label. Every length can be written in millimetres or inches; the renderer normalises to millimetres. The Avery presets are the same thing, generated from published stock dimensions.

  2. 2

    Add records

    Records are a {"schema": [...], "records": [...]} document: one record per label, one key per field the template references. Type them into the table, paste them into the JSON editor, or import a CSV (header row required) or JSON file. Import is parsed in memory; nothing is stored on the server.

  3. 3

    Download the PDF

    The preview above is a render of the real PDF, so what you check is what prints. When it looks right, export it — or run the same job from the command line with label-sheet generate and keep it in a script.

Template JSON

This is data/templates/labels/basic-address.json, shipped with the package and selectable above. A label template is a page, a grid, and a list of elements positioned relative to the top-left of one label. 

{
  "template_type": "label",
  "name": "basic-address-labels",
  "page": {
    "width_mm": 215.9,
    "height_mm": 279.4
  },
  "grid": {
    "rows": 10,
    "cols": 3,
    "margin_left_mm": 4.7625,
    "margin_top_mm": 12.7,
    "margin_right_mm": 4.7625,
    "margin_bottom_mm": 12.7,
    "gap_x_mm": 3.175,
    "label_width_mm": 66.675,
    "label_height_mm": 25.4
  },
  "elements": [
    {
      "type": "text",
      "x_mm": 4.0,
      "y_mm": 3.0,
      "width_mm": 58.0,
      "height_mm": 7.0,
      "field": "name",
      "font_name": "Helvetica-Bold"
    },
    {
      "type": "text",
      "x_mm": 4.0,
      "y_mm": 11.0,
      "width_mm": 58.0,
      "height_mm": 8.0,
      "template": "{address_1}\n{address_2}",
      "font_size_pt": 8.0
    },
    {
      "type": "barcode",
      "x_mm": 4.0,
      "y_mm": 18.0,
      "width_mm": 50.0,
      "height_mm": 6.0,
      "field": "sku"
    }
  ],
  "metadata": {
    "equivalent_to": "Avery 5160 / 5260 / 5960 / 8160",
    "source": "Avery 5160 datasheet: 8.5 x 11 in sheet, 0.1875 in side margins, 0.5 in top/bottom margins, 2.75 in horizontal pitch, 1 in vertical pitch"
  }
}
page
The sheet of stock: width_mm and height_mm. 215.9 × 279.4 mm is US Letter.
grid
rows and cols, the four page margins, the gaps between labels, and the label size. Give the label size or let it be derived from the page, margins and gaps — if both are given they must agree within the renderer’s tolerance, otherwise you get a geometry error instead of a silently wrong sheet.
elements
What is drawn inside one label, repeated in every slot. Coordinates are measured from the top-left corner of the label, not of the page. Three types: text (field or template, font_name, font_size_pt, align: left / center / right / justify, rotation_deg), barcode (barcode_type: code128 / ean13 / qr), and image (a sandboxed asset name plus a fit mode).
_mm and _in
Every length key accepts either suffix — width_mm or width_in. Use whichever matches the stock you bought; the renderer normalises to millimetres and remembers the unit you authored in so the file round-trips unchanged.
Field references
"field": "name" prints one value. "template": "{address_1}\n{address_2}" composes several, and \n is a real line break. Only {identifier} placeholders are substituted — there is no expression language, so a record value can never execute anything.

A text layout is the second half of the pair: the same geometry, a different arrangement. Select one in Text layout above to reuse a sheet’s grid with different elements.

Record documents look like this — a bare JSON array is accepted on import and normalised to the object form: 

{
  "schema": ["name", "address_1", "address_2", "sku"],
  "records": [
    {
      "name": "Ada Lovelace",
      "address_1": "12 Analytical Engine Way",
      "address_2": "London",
      "sku": "AL-1001"
    }
  ]
}

CLI

The web app is a front end for the same library the command line uses. Anything you can preview here you can put in a Makefile. 

# Render a sheet from a template and a record document
label-sheet generate basic-address out.pdf --records records.json

# Show every template the catalogue could load, with its grid and fields
label-sheet list-templates

# Write an Avery preset out as a template JSON you can edit
label-sheet avery-template 5160 out.json

Copy CLI command in the Export section writes the exact invocation for the settings you have chosen, omitting every flag that is already at its default.
